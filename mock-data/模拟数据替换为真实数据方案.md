# 模拟数据 → 真实数据 替换方案（Mock-to-Real Migration Plan）

> 文档状态：已分析 · 待评审实施
> 关联目录：`frontend/`（前端）、`mock-data/`（模拟数据）、`docs/api/`（OpenAPI 契约）
> 唯一事实来源：`docs/api/` 下 7 份 OpenAPI 3.0.1 契约

---

## 1. 现状梳理：当前三层 Mock 架构

当前数据链路共三层，前端页面**不直接**访问 `mock-data/*.json`，而是经过 Nitro 服务端端点：

```
Browser（Nuxt SSR 页面）
   ↓ 调用 composables/useApi.ts（$fetch）
   ↓ /api/xxx（apiBase 默认 '/api'）
Nitro Server 端点  server/api/[...path].ts（catch-all）
   ↓ resolveMockFile() 路径映射 + readMockData() 读取
mock-data/*.json（61 个文件 / 100 条记录 / source_type:"simulated"）
```

| 层 | 位置 | 职责 |
|---|---|---|
| 数据层 | `mock-data/*.json` | 静态 JSON，统一响应 `{code, message, data, timestamp}`，记录带 `source_type: "simulated"` 标记 |
| 服务层 | `server/api/[...path].ts` + `server/utils/mock.ts` | 把前端请求路径映射为 mock 文件并原样返回 |
| 前端访问层 | `composables/useApi.ts` + `nuxt.config.ts` | `runtimeConfig.public.apiBase` 为空时走 `/api`（mock），非空时直连网关 |

**现有代码已声明的切换方式**（`useApi.ts:26-28`、`nuxt.config.ts:15-22`、`frontend/README.md:87-100`）：
> "仅需把 `runtimeConfig.public.apiBase` 指向真实 API 网关，前端代码零改动。"

## 2. 核心结论（必须先纠正的认知）

**⚠️ "只需改 apiBase 即可零改动切换" 的声明，在 `docs/api/` OpenAPI 契约前提下不成立。** 存在两类结构性差异：

### 2.1 路径契约不一致（前端路径 ≠ OpenAPI 路径）

- 前端请求路径：`/index`、`/domains/{domain}/scenarios`、`/domains/{domain}/runs` …
- OpenAPI 真实路径：`/api/v1/{domain}/scenarios`、`/api/v1/{domain}/runs/{run_id}` …

`/domains/{domain}/...` 与 `/api/v1/{domain}/...` 前缀不同，直接设置 `apiBase` 后真实网关会返回 404。

### 2.2 前端多个"聚合/列表"接口在 OpenAPI 中不存在

前端按"一页一请求"设计，而 OpenAPI 是按"资源原子接口"设计。**有 5 个前端接口在后端 OpenAPI 中没有对应 GET 接口**（详见 §4 缺口清单），这些是替换时必须解决的核心阻塞点。

### 2.3 运行详情：mock 单文件聚合 vs 真实 5 个原子接口

- mock：`run-details/{id}.json` 一个文件同时包含 `workflow / metrics / logs / artifacts`；
- 真实：OpenAPI 拆分为 `GET /runs/{run_id}`、`/workflow`、`/metrics`、`/logs`、`/artifacts` 五个独立接口。

### 3.3 字段契约对比结论

- **命名**：OpenAPI 与前端 `types/index.ts` 均为 snake_case（`run_id`、`scenario_id`、`cluster_name`…），字段级基本对齐 ✅
- **统一响应**：`{code, message, data, timestamp}` 一致 ✅
- **执行模式枚举**：OpenAPI 定义 `execution_mode ∈ {real, simulated, replay}`；mock 当前为 `simulated`，真实后端应为 `real` ✅ 前端无需感知
- **source_type**：mock 携带 `source_type: "simulated"`，真实数据不应携带或为其他值；前端当前无强依赖（`useFormat.ts` 不消费该字段），仅作为数据溯源标记

## 5. 候选方案对比

### 方案 A：BFF 反向代理 + 路径映射/聚合（Nitro 网关层，推荐）
在 `server/api/[...path].ts` 中由"读 mock"升级为"网关转发器"：按映射表转发到真实网关，在服务端完成路径转换与聚合；`DATA_SOURCE` 环境变量控制 mock/real 切换，可灰度回退。

| 优点 | 缺点 |
|---|---|
| 前端页面与 `useApi.ts` **零改动** | 需维护映射表与聚合逻辑（代码量中等） |
| 可在服务端注入鉴权 Token，规避 CORS | 聚合接口（run-detail 1→5）依赖真实后端延迟，需并行 + 超时 |
| 可加缓存（scenarios/index 等低频变更数据） | 缺失接口需"垫片"过渡 |
| 灰度切换/回退成本最低 | — |

### 方案 B：前端按 OpenAPI 契约直连改造
改 `useApi.ts` 所有方法为 OpenAPI 路径 + 重写页面数据组装（runs 列表、详情 5 请求合并等），直接设 `apiBase`。

| 优点 | 缺点 |
|---|---|
| 无中间层，链路最短 | **改动面大**：几乎每个页面都要改请求逻辑 |
| 后端契约即唯一真相 | 5 个缺失接口依然要后端补，否则页面直接空白 |
| — | 鉴权/CORS/缓存/错误处理全部落回前端，复杂度上移 |

### 方案 C：契约驱动 + Adapter 数据源 + 渐进式替换（业界最佳实践，推荐与 A 组合落地）
1. 用 `openapi-typescript` 从 7 份 OpenAPI **自动生成 TS 类型**，替换/校验手工 `types/index.ts`，根治字段漂移；
2. `useApi` 抽象数据源 `DataSource`：`MockDataSource`（现状）与 `HttpDataSource`（真实网关），按 `dataSource` 切换；
3. 后端补齐缺失接口前，BFF/Adapter 从 mock 文件垫片返回；
4. 逐页面灰度替换 + 字段对拍脚本验收。

| 优点 | 缺点 |
|---|---|
| 类型/契约从源头对齐，杜绝隐性字段错误 | 实施周期最长（分阶段） |
| 可 mock/real 并存，风险最低 | 需要团队协作（后端补齐接口） |

## 6. 推荐方案详设：方案 A + C 组合（BFF 网关 + 契约驱动 + Adapter）

### 6.1 目标架构

```
Browser（Nuxt SSR 页面 · 零改动）
   ↓ useApi.ts（零改动，仍请求 /api/...）
Nitro 端点 server/api/[...path].ts（升级为网关转发器）
   ├─ dataSource=mock → 走现有 resolveMockFile()（保留回退）
   └─ dataSource=real → gateway.ts：
        ├─ API_MAP      前端路径 → 真实网关路径（含路径参数重写）
        ├─ Aggregator   并行请求 + 合并（scenario-details/params-schema/benchmark/run-detail/index）
        ├─ Cache        TTL 缓存低频数据（index/scenarios/params-schema）
        ├─ Auth         服务端注入 Authorization（apiToken 仅存服务端）
        └─ Fallback     真实后端失败 → 记录日志 + 降级（返回 mock 垫片）
        ↓ $fetch（ofetch，timeout）
真实 API 网关（FastAPI · 按 docs/api OpenAPI 部署）
```

### 6.2 配置设计（nuxt.config.ts）

```ts
runtimeConfig: {
  public: {
    dataSource: process.env.NUXT_PUBLIC_DATA_SOURCE || 'mock', // 'mock' | 'real'
    apiBase: '',          // 真实网关，如 https://api.example.com/api/v1
    apiTimeoutMs: 8000,   // 转发超时
  },
  // 仅服务端可见，不下发浏览器
  apiToken: process.env.API_TOKEN || '',
}
```

### 6.3 网关转发器核心设计（新增 `frontend/server/utils/gateway.ts`）

```ts
// 前端路径（useApi 发出的）→ 真实网关请求
type Route = { path: string; method?: 'GET' | 'POST' }
const API_MAP: Array<{ prefix: string; route: (parts: string[]) => Route | null }> = [
  // 运行详情：/domains/:d/runs/:id → 5 个子接口聚合
  {
    prefix: 'domains',
    route: ([, domain, kind, id]) =>
      kind === 'runs' && id
        ? { path: `/api/v1/${domain}/runs/${id}` } // Aggregator 再并发 workflow/metrics/logs/artifacts
        : null,
  },
  // 场景类：/domains/:d/scenarios → /api/v1/:d/scenarios
  { prefix: 'domains', route: ([, domain, kind]) =>
      kind === 'scenarios' ? { path: `/api/v1/${domain}/scenarios` } : null },
  // 多中心：/multicenter/deployment-matrix → /api/v1/multicenter/functions/deployment-matrix
  { prefix: 'multicenter', route: ([, kind]) =>
      kind === 'deployment-matrix' ? { path: '/api/v1/multicenter/functions/deployment-matrix' } : null },
  // …其余按 §3 映射表逐条登记
]

export async function proxyRequest(path: string): Promise<unknown> {
  // 1. 查映射表 → 无则 404
  // 2. Aggregator 需聚合的 → Promise.all 并行拉取子资源再合并（run-detail 5 请求）
  // 3. 缺失接口（index/runs 列表/operators/invocations 列表/migrations 列表）→ 垫片：读 mock-data 或 504 明确报错
  // 4. Cache：index/scenarios 等打 TTL 缓存（Nitro useStorage）
  // 5. 统一错误：真实网关非 200 → 抛 h3 createError，附上游 message
}
```

### 6.4 契约驱动：类型生成（消除手工类型漂移）

```bash
npx openapi-typescript docs/api/Topic5-AI-LLM-Training.openapi.json -o frontend/types/generated/llm.d.ts
# …7 份 OpenAPI 逐一生成，frontend/types/index.ts 改为 re-export generated types
```
> 目标：`types/index.ts` 中每个 interface 都与 OpenAPI schema 同源，替换时按 `npm run typecheck` 兜底。

### 6.5 前端 useApi 可选增强（走 BFF 时非必需）

若选择**方案 B**（直连）或后端直接补齐接口，`useApi.ts` 需：
- `request<T>()` 增加 `timeout`、`headers`（Authorization）、`credentials` 处理；
- 列表接口支持分页参数透传（`page`/`page_size`/`status`）；
- 动态数据页面（运行详情、运行列表）增加轮询（5–10s）与增量日志加载（`next_offset`/`has_more`）。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 字段漂移（mock 与真实后端不一致） | 页面渲染错乱 | 阶段 0 用 openapi-typescript 生成类型；对拍脚本兜底 |
| 5 个缺失接口未排期 | 首页/列表页空白 | BFF 垫片从 mock-data 返回并标注；明确接口清单给后端 |
| 运行详情 1→5 请求延迟放大 | 详情页变慢 | Promise.all 并行 + 超时 + 页面 loading；日志改增量加载 |
| 动态数据（进度/日志实时性） | 展示过期 | 运行页轮询 5–10s；`next_offset` 增量拉取日志 |
| 真实网关鉴权/CORS | 请求失败 | Token 由 Nitro 服务端注入（不进浏览器）；服务端转发天然规避 CORS |
| 上游 500/限流 | 页面报错 | 统一错误映射 + 降级回退 mock；缓存高频读接口 |
