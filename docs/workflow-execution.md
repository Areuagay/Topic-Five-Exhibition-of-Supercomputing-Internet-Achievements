# 工作流依赖与执行

新提交任务根据 `backend/workflow-engine.js` 中的显式算子规则生成 DAG，不再按勾选顺序统一串行。

- 数据准备完成后，无相互依赖的算子分支可以同时运行。
- 依赖关系按选中的算子投影；未选中的准备阶段视为已有输入，仍保留已选上游之间的传递依赖。
- 下游必须等全部直接上游成功完成，结果整理节点必须等待所有末端分支。
- 并行支路可以包含不同数量的串行算子。一条支路的第二个算子在自己的前置算子完成后即可执行，不必等待另一条支路；只有共同的汇合节点等待两边全部完成。
- 并行分支使用可复现的不同模拟耗时，先完成的分支显示等待汇合；纯串行链保持原有步进速度。
- 未登记依赖规则的旧算子保持所选顺序的串行结构。历史活动任务保留已提交拓扑，已完成的模拟体验任务更新为对应依赖布局。
- 任务执行仍为展示系统的本地模拟流程；这里的连接规则不是平台下发的真实调度 DAG，也不会调用算子容器。

典型结构：

| 场景 | 依赖规则 |
| --- | --- |
| 地球动力学 | 独立求解器分别运行，最后统一整理 |
| 模型训练 | 数据准备 → 多个独立训练方案 → 汇总 |
| 药物筛选 | 配体准备与受体网格准备并行 → CPU/GPU 对接分支 → 能量与合理性分析 |
| 仿真计算 | 网格 → 初场 → 划分 → 求解器分支 → 重构 → 导出与指标提取 |
| 材料计算 | 结构处理、电子结构与分子动力学按各自依赖链执行 |
| 汽车设计 | 独立评估并行，演化与输运后处理保留其前置依赖 |

这些独立方案在演示中分别消费各自输入，不表示不同求解器共享同一个可写计算目录。实际平台接入时，应由真实输入输出契约替换本地规则。

执行进度由时间推进，读取频率不会加速任务；重启保留每个分支的进度。失败分支阻断其下游与最终输出。只有包含最终输出节点在内的全部节点成功后才开放结果。

前端按真实依赖进行分层布局，拉开并行支路间距，使用独立连接端口和避开节点的圆角折线。长短不同的串行支路在分流与汇合之间整体居中，保留支路内间距和两端连线走廊；复杂依赖存在障碍时只移动到安全位置。确需交叉的依赖线以底色描边区分。

布局仅在拓扑、节点名称或实测标题高度变化时重新计算；进度刷新保留节点位置、连线路径以及用户缩放与拖动位置。首次显示优先保证文字可读，较大的图可拖动查看；点击“适应工作流视图”可完整查看所有节点与连线。进度条平滑过渡，运行中的连接显示流向，减少动态效果设置会关闭这些动画。
