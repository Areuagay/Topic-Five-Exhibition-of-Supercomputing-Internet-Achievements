# 工作流依赖与执行

新提交任务根据 `backend/workflow-engine.js` 中的显式算子规则生成 DAG，不再按勾选顺序统一串行。

- 数据准备完成后，无相互依赖的算子分支可以同时运行。
- 依赖关系按选中的算子投影；未选中的准备阶段视为已有输入，仍保留已选上游之间的传递依赖。
- 下游必须等全部直接上游成功完成，结果整理节点必须等待所有末端分支。
- 并行支路可以包含不同数量的串行算子。一条支路的第二个算子在自己的前置算子完成后即可执行，不必等待另一条支路；只有共同的汇合节点等待两边全部完成。
- 运行时长由所选算子资源估算（`backend/operator-plan.js` 的 `estimatePlanSeconds`，约 4–15 分钟），并按算子的 CPU / GPU 规模分配各节点计划区间。进度条严格按墙钟时间推进，不再用 1.3 秒 tick 压缩演示时长。
- 历史运行记录保留原来的累计耗时；其起止时间按 `start_time + elapsed_seconds` 对齐，避免出现“起止只差几十秒、耗时却显示 40 分钟”。
- 工作流节点的 CPU 核数、GPU 卡数、内存和运行消耗核时全部来自算子库；运行摘要按算子节点汇总，不再使用运行记录里写死的整机分配值。
- 旧算子（`fd-wave-solver`、`fft-operator`、`band-dos-post` 等）通过 `scripts/migrate-run-operators.mjs` 迁移到当前算子库，并同步 `.runtime-data/` 中已创建的历史任务。
- 未登记依赖规则的旧算子保持所选顺序的串行结构。模拟体验任务按模板版本更新工作流；活动任务沿用原计划总时长与墙钟进度，补齐当前模板的节点和依赖。
- 任务执行仍为展示系统的本地模拟流程；这里的连接规则不是平台下发的真实调度 DAG，也不会调用算子容器。

典型结构：

| 场景 | 依赖规则 |
| --- | --- |
| 地球动力学 | 数据与环境并行准备 → 区域划分 → 求解分支 → 迭代收集 → 集成分析 → ParaView 转换 → 剖面生成 → 编号归档 |
| 模型训练 | 数据准备 → 多个独立训练方案 → 汇总 |
| 药物筛选 | 配体准备与受体网格准备并行 → CPU/GPU 对接分支 → 能量与合理性分析 |
| 仿真计算 | 网格 → 初场 → 划分 → 求解器分支 → 重构 → 导出与指标提取 |
| 材料计算 | 结构处理、电子结构与分子动力学按各自依赖链执行 |
| 汽车设计 | 独立评估并行，演化与输运后处理保留其前置依赖 |

这些独立方案在演示中分别消费各自输入，不表示不同求解器共享同一个可写计算目录。实际平台接入时，应由真实输入输出契约替换本地规则。

地球动力学两个板块采用上传的 [geodynamics-workflow-key.json](workflows/geodynamics-workflow-key.json) 中的 `simulate` 路径实体与共享后处理依赖：

- “地震波传播模拟”固定保留现有 SUPG 接口；“板块构造数值模拟”固定保留现有 Uzawa 接口。固定算子自动选中，不能通过单选、已选标签或“清空可选算子”移除；提交接口也会校验。
- 其余三个领域算子为可选算子，仍可按场景推荐、类别、运行环境和关键词筛选。类别策略集中在 `shared/geodynamics-workflow.js`，同步平台算子库不会覆盖它。
- 数据读取、CitcomCU 镜像拉取、求解区域划分、迭代计算与结果收集、数据集成分析、CitcomCU 转 ParaView、剖面生成、结果编号归档共 8 个内置实体，自动加入工作流，不进入算子选择和平台算子库。
- 同时选择 Uzawa 与 SUPG 时，先执行速度/压力约束求解，再执行稳定化输运阶段。CitcomS 全球/区域调用作为独立对照分支，迭代收集等待所有分支完成。这是展示编排，不表示两个独立 HTTP 接口已经接入 CitcomCU 内部迭代循环，也不将 SUPG 描述为完整地震波求解器。
- 波传播板块的剖面实体显示“波场快照与剖面”，板块构造板块显示“温度与流速剖面”。每个实体均有独立计划耗时、状态、进度和日志，进度直接显示在 DAG 节点内；暂停、恢复、重启与结果开放沿用统一状态机。
- `prepare` / `post` 保留历史节点 id，并通过 `entity_id=read/package` 对应原工作流实体；其余实体 id 与上传文件一致。归档显式依赖分析快照、转换网格和剖面图像，全部完成后才开放结果。
- 历史记录按地球动力学模板版本自动补齐实体。实体不带虚构的 CPU/GPU/内存声明，算子资源统计仍取自平台算子库。

上传文件中的 `replay` 是“读取已有 CitcomCU 结果”的替代入口。当前两个板块提交的是新计算任务，因此采用 `simulate` 路径；未将已有结果读取与新计算强行并行，也未增加缺少输入契约的回放入口。

其他五个领域的十个板块分别维护固定流程模板，定义在 `backend/domain-workflows.js`：

| 领域 | 板块 | 固定内置节点 | 准备、计算衔接与结果校验 |
| --- | --- | ---: | --- |
| AI模型训练 | 大语言模型预训练 | 13 | 语料/词表/权重检查、分片与并行策略、训练分支、检查点校验、独立验证、吞吐分析 |
| AI模型训练 | PINN科学计算 | 14 | PDE/初边值/采样检查、物理特征与模型初始化、学习分支、物理残差/边界误差/参考解比较 |
| 汽车设计 | 整车碰撞仿真 | 15 | 网格/材料/接触/边界检查、算例分区、评估分支、能量/加速度/侵入量并行核验 |
| 汽车设计 | 结构疲劳寿命 | 16 | 载荷清洗、S-N曲线、雨流计数、响应恢复、均值应力修正、损伤累积、热点与寿命统计 |
| 仿真计算 | 集群协同控制 | 12 | 初态/通信拓扑/编队检查、环境评估链、轨迹收集、编队/连通/机间间隔并行评价 |
| 仿真计算 | 航迹规划避障 | 17 | 地图/障碍物/任务检查、自由空间、环境评估、候选航迹、净空/运动学检查、冲突消解、平滑后复核 |
| 药物设计 | 化合物虚拟筛选 | 11 | 分子与蛋白双支路检查、配体分片/结合口袋准备、CPU/GPU对接、评分对齐、候选筛选与口袋复核 |
| 药物设计 | ADMET性质预测 | 10 | 分子/参考数据/模型检查、描述符对齐、所选分子分析、参考覆盖与成药风险并行评价 |
| 材料计算 | 能带与态密度 | 18 | 晶体/赝势/k点检查、标准晶胞、输入契约、SCF收敛、能带与DOS分支、费米对齐、带隙与拓扑汇合 |
| 材料计算 | 高通量材料筛选 | 19 | 结构登记/去重/成分筛查、批次/势函数/系综、电子与动力学分支、稳定性汇合、性质排名与多样性筛选 |

这些数字仅统计固定内置实体，DAG 总节点数还包括本次选择的算子。例如全部选择领域算子时，各模板分别包含 22、23、29、30、25、30、20、19、32、33 个节点；场景推荐组合按实际选择生成。

- 固定实体不会进入算子库和算子选择列表，进度、节点类别、处理内容与计划耗时直接显示在 DAG 中，不增加额外的实体列表板块。
- 现有注册算子保留原依赖，并插入相应准备与校验阶段。未选算子对应的接口位置收缩到已准备的输入或中间结果，不会伪造一次未选择的算子调用；固定实体始终保留。
- 模板先校验完整依赖图，再投影所选算子，并移除已通过其他路径保证的重复依赖。节点顺序按拓扑生成，汇合节点等待所有必要分支。
- 每个固定实体有自己的计划区间、状态、进度、日志和处理说明；部分实体按处理量赋予不同的计划权重。CPU/GPU/内存和核时仍只按所选注册算子汇总。
- 每个模板单独版本化。已保存的模拟运行在后端加载时补齐固定实体并保存，原来的算子组合、结果内容与成功记录耗时继续保留。
- 这些是现有展示系统的模拟执行阶段。仓库中部分场景名称与平台登记算子并非一一对应：树模型不等于 PINN 求解器，OpenFOAM 场算子不等于集群控制/路径规划器，分子对接分析接口也不等于已接入 ADMET 多任务模型。固定阶段按场景准备和评价这些输出，不宣称新增真实科学求解容器；真实接入仍需对应输入输出契约与执行适配器。

执行进度由时间推进，读取频率不会加速任务；重启保留每个分支的进度。失败分支阻断其下游与最终输出。只有包含最终输出节点在内的全部节点成功后才开放结果。

前端按真实依赖进行分层布局，拉开并行支路间距，使用独立连接端口和避开节点的圆角折线。长短不同的串行支路在分流与汇合之间整体居中，保留支路内间距和两端连线走廊；复杂依赖存在障碍时只移动到安全位置。确需交叉的依赖线以底色描边区分。

布局仅在拓扑、节点名称或实测标题高度变化时重新计算；进度刷新保留节点位置、连线路径以及用户缩放与拖动位置。首次显示优先保证文字可读，较大的图可拖动查看；点击“适应工作流视图”可完整查看所有节点与连线。进度条平滑过渡，运行中的连接显示流向，减少动态效果设置会关闭这些动画。
