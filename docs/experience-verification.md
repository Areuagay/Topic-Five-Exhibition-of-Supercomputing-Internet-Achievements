# 六领域六步体验：运行与验证

本轮覆盖数据准备按钮与上传反馈、六领域十二场景共享交互、运行进度、结果入口及操作体验。附件 P0/P1/P2 用作参考，未引入 P2 的迁移、扩缩容、函数服务或第三方验收功能。

## 启动

在仓库根目录运行 `node backend/server.js`，在 `frontend` 目录运行 `npm run dev -- --host 127.0.0.1 --port 3000`。

- 前端：http://127.0.0.1:3000
- 后端：http://127.0.0.1:3001/api/v1
- 本地模拟状态：`.runtime-data/`；可通过 `MOCK_RUNTIME_DIR` 指定目录。
- 测试不写入 `mock-data/`，上传和新建任务不会改写版本控制中的演示种子。

## 演示操作

1. 进入任一场景的数据准备页。固定数据条目保留，内置数据直接就绪；其他数据可上传或移除。未上传时大小、来源、更新时间显示“—”；时间单独列出。
2. 点击“上传数据”，依据条目大小压缩模拟为约 2–12 秒，绿色扫光随百分比推进。支持取消，离开数据准备页会取消尚未确认的上传。完成时保留 100% 并淡出；取消时停止进度、回退淡出并显示“已取消”。
3. 点击“导入并继续”，进入资源调度。对应支持中心的 CPU、内存展示随已导入数据变化；重复导入不重复累计。全部已导入时按钮显示“前往资源调度”。
4. 选择算子并点击“提交并编排”。未提交当前选择时，第 4–6 步一起锁定，直接访问这些步骤的网址或通过浏览器返回时也校验提交条件；成功提交后一起解锁并生成独立运行记录。上一步按 6→5→4→3 相邻返回。已提交方案可刷新恢复；修改选择或恢复推荐方案后需重新提交。未提交时查看历史任务请使用顶部“运行记录”；解锁后监控中的“查看工作流”打开对应任务详情。
5. 工作流、监控列表和详情由同一服务端时间推进；轮询次数不会加速任务。刷新或重启后继续保留任务。
6. 成功、100% 且有结果的记录可查看专业图表与成果；历史无结果记录、运行中、失败和停止记录不开放最终结果。预置状态与本次运行有不同标识。

上传是预置条目的模拟传输，没有发送用户本地文件。计算进度、耗时、核时和专业结果均为模拟展示。上传预计时间为压缩演示时长，计算耗时显示累计模拟耗时，不等于观看演示的墙钟时间。

## 自动验证

根目录执行：

```powershell
node --test frontend/tests/*.test.mjs backend/tests/*.test.mjs
```

`frontend` 目录执行 `npm run typecheck` 与 `npm run build`。若需要保持开发服务运行，可通过 Nuxt Kit 指定独立 `buildDir` 进行生产构建，避免覆盖开发服务的 `.nuxt`。

浏览器验收脚本需要 Playwright 和 Microsoft Edge；可用 `PLAYWRIGHT_MODULE` 指定工具环境中的 Playwright 包路径，或安装到可解析的 Node 环境。服务启动后运行：

本轮收尾使用 `node scripts/verify_experience_closeout.mjs`，覆盖十二场景的字段和入口校验，以及一次提交、刷新、更改选择、恢复推荐、历史工作流与窄屏检查；会创建一条演示任务。导航规则可单独运行 `node --test frontend/tests/experience-navigation.test.mjs`。以下为前期完整验收脚本，部分按钮定位仍沿用旧文案，不作为本轮检查通过的依据。

```powershell
node scripts/verify_experience_ui.mjs
node scripts/verify_experience_resilience.mjs
node scripts/verify_experience_motion.mjs
node scripts/verify_upload_feedback.mjs
```

第一个脚本覆盖十二场景的上传、导入、提交、动态监控、刷新恢复、完成及结果入口，输出截图和 `.runtime-logs/experience-qa/report.json`。第二个脚本覆盖网络错误恢复、延迟响应竞态、上传失败重试、离开页面取消以及 390px 布局。

第三个脚本覆盖六领域的选中/取消、已选标签、连续点击、选择与筛选交错、步骤动画中断，以及手机布局和系统减少动态效果设置；检查最终状态、残留透明度与变换，不仅检查样式类名。

## 按钮与动效

全站共用配色、边框、控件圆角与文字层级，主要按钮使用纯色，保留悬停抬升、按压回弹和图标反馈，不再使用镜面高光。桌面六步体验使用左侧流程导航，窄屏保持上方导航。Vue Transition 负责步骤内容的短距离进入与交接，导航与筛选指示块连续移动。算子选择联动卡片底色、勾选标记、数量切换和可移除标签，标签区域平滑展开收起。

选择反馈使用独立的 CSS `scale` 动画，筛选列表独立管理 `transform`，避免快速操作时相互覆盖。所有动效尊重 `prefers-reduced-motion`；操作立即更新状态，不等待动画完成。

冷启动时，服务端已渲染的体验控件在 Vue 完成事件绑定后才开放交互，避免首击丢失。监控进度条保留成功、失败等状态色，上传渐变限定在上传区域。

上传期间绿色扫光的前沿随百分比推进，右侧显示进度与取消按钮。完成后显示 100%，短暂停留并淡出；取消时冻结进度、扫光回退淡出，短暂显示“已取消”后恢复上传按钮。移除上传保留红色扫光。通知占据固定位置，不推挤表格，减少动态效果时取消扫光位移。

本轮上传检查确认百分比与扫光位置同步、完成和取消渐隐、进度停止及重试、行高稳定。前期 `verify_upload_feedback.mjs` 的全行穿过断言对应旧版动画。视觉重做前回退点为 `34e2c82`，收尾修改前回退点为 `479117d`。

本地体验前端通过隐藏的独立进程运行，输出位于 `.runtime-logs/frontend-service.out.log` 与 `.runtime-logs/frontend-service.err.log`，关闭验证浏览器不停止前后端。

验收脚本会通过正常接口在本地模拟目录创建演示任务。这些运行记录保留，方便随后人工体验。
